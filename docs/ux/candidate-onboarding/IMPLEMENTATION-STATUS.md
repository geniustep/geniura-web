# رحلة بدء الملف المهني — 31 أكتوبر 2026

## المسار المنفذ
- زر «أنشئ ملفك المهني» يفتح `/[locale]/start`؛ إضافة السيرة أولًا والإدخال اليدوي بديل دائم.
- عند تفعيل `NEXT_PUBLIC_ENABLE_GUEST_CV=true`، يستطيع الضيف رفع PDF/DOCX حتى 5 MiB قبل إنشاء الحساب. تظهر حالة الفحص والمعالجة، ثم اسم وبريد وهاتف مقترحة غير موثقة. يمكن تصحيح الاسم المعروض والبريد قبل تأكيده؛ الاسم المعروض لا يغيّر حسابًا قائمًا.
- يطلب المستخدم إرسال رمز إلى البريد الذي يؤكده بنفسه. لا يكشف وجود الحساب إلا بعد إثبات البريد برمز أحادي الاستخدام. الهاتف اقتراح فقط ولا يُستخدم لمطابقة حساب أو إثبات هوية.
- بعد التأكيد يتوجه إلى تسجيل الدخول أو إنشاء حساب. يحفظ `next=/start?step=claim` دون تكرار بادئة اللغة ودون بيانات شخصية في الرابط.
- عند العودة يُطلب ربط السيرة صراحةً ثم تفتح شاشة مراجعة المعلومات القائمة. لا اعتماد تلقائي ولا استبدال لملف مهني موجود. الربط يتطلب حسابًا مصادقًا وبريده مطابق للبريد المثبت حديثًا.
- إذا انتهى إثبات البريد يُطلب رمز جديد؛ وإذا انتهت المسودة يمكن البدء مجددًا. يمكن حذف المسودة وملفها. لا تُحفظ المسودة في localStorage.
- عند إغلاق المفتاح يبقى المسار السابق: الدخول قبل الرفع باستعمال ResumesPanel؛ هذه حالة التفعيل الافتراضية.
- جميع النصوص متاحة بالعربية والفرنسية والإنجليزية والإسبانية. شاشة البدء noindex وprivate,no-store، والتصميم يستخدم التوكنات والخطوط القائمة وخصائص CSS المنطقية.

## خدمة الخلفية
العمل في [geniura-api#25](https://github.com/geniustep/geniura-api/pull/25)، مستقل عن `Resume.profile`:

| المسار | الطريقة | الوظيفة |
| --- | --- | --- |
| `/api/v1/onboarding/guest-cv` | POST / GET / DELETE | رفع المسودة، حالتها، حذفها |
| `/api/v1/onboarding/guest-cv/email-code` | POST | طلب رمز بعد تأكيد عنوان البريد |
| `/api/v1/onboarding/guest-cv/verify-email` | POST | إثبات البريد ثم توجيه الحساب |
| `/api/v1/onboarding/guest-cv/claim` | POST | ربط المسودة بالحساب المصادق |

الملكية عبر ملف ارتباط عشوائي HttpOnly، وبصمة HMAC فقط في قاعدة البيانات. الصلاحية 24 ساعة؛ التنظيف الدوري يحذف البايتات والصفوف المنتهية. الملفات في حجر خاص ثم تخزين معتمد خاص بعد الفحص. الاستخراج محلي محدود الذاكرة والوقت. رمز البريد صالح 10 دقائق وبحد خمس محاولات وخمس رسائل للمسودة مع مهلة دقيقة بين الرسائل. يوجد CSRF وتحديد معدل بحسب عنوان المصدر المرئي للخادم.

مفتاح الخلفية `FEATURE_GUEST_CV=false` افتراضيًا ويتطلب أيضًا `FEATURE_CV_UPLOAD=true`. مسار ClamAV مدعوم؛ الفحص الخارجي المرتبط بـResume غير مدعوم للضيف حاليًا ويُرفض صراحةً، وكذلك وضع اختبار staging الهيكلي. لا يجوز تفعيل الضيف عبر تعطيل فحص الإنتاج.

## التفعيل والتحقق
يلزم تطبيق migration `0005_guestresumedraft`، وتخزين خاص، وفاحص مدعوم، وعامل Celery، وتشغيل Celery Beat للتنظيف، وبريد معاملات. بعد نجاح CI والتحقق على staging يمكن تفعيل مفتاح الخلفية ثم مفتاح الواجهة وإعادة بنائها. يلزم التحقق من إعداد المصدر الموثوق لتحديد المعدل خلف الـBFF/proxy.

اختبارات الواجهة تغطي الرفع المجهول، الترحيب القابل للتصحيح، عدم توجيه الحساب قبل الإثبات، الحذف، والربط الصريح بعد الدخول. اختبارات الخلفية تستعمل ملفات وعناوين مصطنعة، وتشمل المحلّل الفعلي لـPDF/DOCX، الملكية، CSRF، المحاولات، انتهاء الإثبات والمسودة، فشل الفحص، الربط المتكرر، والعودة من تسجيل الدخول الفعلي. نجاح الاختبارات المحلية لا يثبت دقة الاستخراج على كل سيرة أو عمل مزود البريد والفاحص المنشورين. اختبارات قاعدة البيانات المحلية تستخدم PostgreSQL المضمّن PGlite دون اختبارات تزامن؛ يلزم CI PostgreSQL الأصلي والتحقق المتصفحي قبل التفعيل.

لم يحدث نشر أو تفعيل لهذا المسار. التنفيذ محفوظ في طلبي دمج منفصلين للواجهة والخلفية.
