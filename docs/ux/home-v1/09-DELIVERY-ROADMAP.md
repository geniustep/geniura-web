# 09 — خارطة التصميم والتنفيذ

**التسليم الحالي:** توحيد وثائق المصادر ومطابقتها مع `dev`، وليس تعديل التطبيق.

## المرحلة A — مراجعة وثائق المشروع (هذه الدفعة)

- تقييم الحزمة الأصلية في مشروع ChatGPT وملف MASTER ووثائق المشروع على GitHub.
- توثيق اختلاف نص Hero وشجرة المسارات، وترجيح خيار **للوثائق فقط** مع إبقاء القرار التنفيذي مفتوحًا.
- تصحيح مصفوفة API بناء على `contracts/source.json` والعميل المولد.
- اعتماد مكان واحد `docs/ux/home-v1/` وسجل مصادر ومخاطر، دون تغيير كود أو فرع الإنتاج.

**مخرج المرحلة:** 11 ملف Markdown مرجعي، لا واجهات منشورة.

## المرحلة B — تصميم الواجهة العامة

- تصميم 2–3 تخطيطات ضمن هوية Nuit، لا ثلاث هويات جديدة.
- صياغة Hero نهائية بعد مراجعة النصوص بكل اللغات، والتحقق من CTA وSEO وملاحظات الثقة.
- اختيار تصميم Desktop/Mobile وحالات الفراغ والخطأ، مع معاينة توضيحية آمنة.

**بوابة القبول:** UX-PUBLIC-001 ومعايير الملف 08؛ اعتماد بصري من مالك المشروع قبل برمجة.

## المرحلة C — تطوير الصفحة العامة لاحقًا

- إعادة استعمال `app/[locale]/page.tsx` و`features/home/latest-jobs.tsx` والمكونات والترجمات القائمة.
- الحفاظ على وظائف البحث العامة وعقود SEO، والتعامل مع ميزات CV غير المتاحة.
- اختبارات `pnpm check` و`pnpm build` وE2E ثم Preview على `dev` بعد تكليف صريح.

## المرحلة D — لوحة الباحث

- تأكيد شجرة `/workspace/*` مقابل أي مسارات بديلة قبل كتابة App Router.
- ربط الملف المهني الموجود، وأولوية مراجعة CV، وترشيحات الباحث **باستخدام العقد الموجود والتحقق من التشغيل**.
- إضافة حماية noindex/no-store والتوجيه الآمن وعزل بيانات الجلسة.

## المرحلة E — لوحة المؤسسة

- فحص عضويات `Me.memberships` ودور `signup_intent`، وتوثيق تفويض Backend قبل واجهة الشركة.
- استعمال عمليات المؤسسات والإعلانات والترشيحات المولدة، دون اختراع API مسبقًا.
- اختبار عزل A/B والصلاحيات، وحالات onboarding والتعطل.

## المرحلة F — التحسين والإطلاق

- اعتماد مؤشرات أداء مبنية على بيانات وموافقات الخصوصية.
- اختبار المطابقة المفسرة فقط بعد فحوص الجودة والتشغيل.
- لا دمج `main` أو تمكين الفهرسة أو نشر الإنتاج إلا بموافقة مستقلة بعد مراجعة CI/QA.

## صيغة تقرير كل وكيل

الفرع وSHA، ملفات التغيير، عقود API المستعملة، سلوك حالات loading/empty/error/success، نتائج الاختبارات النصية، الفجوات، الأمان، والأمور التي تحتاج مسؤول Backend أو قرار منتج. **لا تخلط التوثيق بقبول الإنتاج**.
