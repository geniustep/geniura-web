# 08 — معايير القبول واختبارات الواجهات

**هذه خطة QA وليست تقرير نجاح.** كل بند أدناه اختبار مطلوب لاحقًا؛ لا تختزل قابلية الاستخدام في مرور البناء.

## 1. الواجهة العامة

- [ ] يفتح `/{locale}` بالعربية والفرنسية والإنجليزية والإسبانية من دون مفاتيح مفقودة.
- [ ] يفهم زائر جديد القيمة الأساسية خلال 5 ثوانٍ، ويرى CTA «أنشئ ملفك المهني» و«أنا صاحب عمل» ورابط الوظائف.
- [ ] البحث والتصفح عبر `/jobs` لا يتطلبان حسابًا.
- [ ] عند عدم وجود وظائف تظهر حالة فراغ صادقة؛ لا بطاقات demo متكررة.
- [ ] عند انقطاع API الوظائف يبقى Hero وروابطه ظاهرين ويعملان.
- [ ] الراتب غير المعلن لا يُستبدل بصفر، و«موثق» لا تُعرض بلا تحقق فعلي.
- [ ] معاينة الملف تحمل وصفًا بأنها توضيحية ولا تحتوي بيانات مرشح حقيقي.
- [ ] روابط canonical/hreflang وOpen Graph وJobPosting/Organization صحيحة دون اختلاق بيانات.
- [ ] لا تفعيل لفهرسة عامة قبل بوابة إطلاق SEO المنفصلة.

## 2. لوحة الباحث

- [ ] مستخدم جديد يدخل مساحة مرشح محمية، ويرى خطوة إنشاء ملف يدوي دون CV إلزامي.
- [ ] غير مؤكد البريد يرى التنبيه المناسب وفق شروط الخادم الفعلية.
- [ ] CV قيد الفحص أو المعالجة يعرض الحالة الحقيقية، وليس نجاحًا مسبقًا.
- [ ] `review_required` يصل إلى مراجعة البيانات وتصحيحها واعتمادها بإجراء صريح.
- [ ] عند الفشل تظل البيانات اليدوية محفوظة؛ لا تواريخ أو تجارب مخترعة ولا ازدواجية.
- [ ] آخر الترشيحات — إذا شُغلت الخدمة — تطابق بيانات العقد، مع تاريخ وحالة صحيحة.
- [ ] لا ترشيحات أو API متعطلة لا يتحولان إلى جدول وهمي أو عداد كاذب.
- [ ] لا توصيات «مطابقة AI» غير مفسرة؛ الوظائف العامة بديل واضح.
- [ ] تغيير الخصوصية لا يحدث بمجرد فتح اللوحة؛ لا مشاركة صامتة.
- [ ] مستخدم آخر لا يستطيع جلب الملف أو السيرة أو ترشيحات لا تخصه.

## 3. لوحة المؤسسة

- [ ] الحساب بلا عضوية يرى onboarding مؤسسيًا مشروطًا وليس لوحة ملفقة.
- [ ] المؤسسة قيد التحقق لا تُعرض «موثقة».
- [ ] `signup_intent` وحده لا يمنح أي صلاحية مؤسسية.
- [ ] عضو `viewer` لا يرى أدوات تعديل والخادم يرفض أي تغيير غير مأذون.
- [ ] لا تسرب بيانات بين A وB عند تبديل المؤسسة أو الرجوع للخلف أو إنهاء الجلسة.
- [ ] بيانات الترشيحات تخص وظائف المؤسسة فقط، ولا تكشف مرشحًا خارج ترشحه/إذنه.
- [ ] زر نشر العرض يظهر ويعمل فقط مع الصلاحية وfeature flag والتشغيل الحقيقي.
- [ ] لا شارة تحقق للوظيفة لمجرد تحقق المؤسسة؛ لا إعلان نشر مجاني بلا اعتماد تجاري.
- [ ] خطأ API لا يتحول إلى أصفار أو رسائل «لا ترشيحات» مضللة.

## 4. المصادقة والمسارات

- [ ] `next` الحالي يعود إلى المسار الأصلي بعد مصادقة وصلاحية ناجحتين.
- [ ] اختبار منع open redirect: روابط خارجية و`//` وbackslash وترميزات خطرة.
- [ ] لا تحويل إلى `/workspace` قبل وجود صفحة حقيقية محمية.
- [ ] المسارات الخاصة كلها `noindex` و`Cache-Control: private,no-store`، ولا تظهر في sitemap أو shared cache.
- [ ] دخول مباشر إلى مساحة غير مصرح بها يرد 401/403 آمنًا، ولا يسرب اسم مؤسسة أخرى.
- [ ] الخروج وإعادة تسجيل الدخول بحساب آخر لا يعرضان بيانات الجلسة السابقة.

## 5. اللغة والأداء والإتاحة

- [ ] 320/375/390/768/1280/1440 CSS px بلا تمرير أفقي.
- [ ] دعم RTL عربي، وLTR فرنسي/إنجليزي/إسباني، بما فيها أسماء المهن الفرنسية داخل واجهة عربية.
- [ ] دعم لوحة المفاتيح وFocus وEscape للقوائم وهدف WCAG 2.2 AA، مع فحص axe ومراجعة بشرية.
- [ ] حالات التحميل ثابتة دون اهتزاز مفرط، وCore Web Vitals تفحص في ظروف هاتف ممثلة.
- [ ] ينجح `pnpm check` و`pnpm build` وPlaywright E2E بعد **تغييرات التنفيذ**، مع regression للحساب/الملف المهني.
- [ ] لا طلب لقطات شاشة من وكيل Windows؛ أدلة نصية/DOM/HTTP كافية عند الحاجة.

## 6. بوابة التسليم

لا وصف `PASS` لأي بند دون اختبار فعلي؛ توثيق SHA والفرع والبيئة والعمليات المختبرة والفشل/المخاطر. لا نشر إنتاج ولا تعديل `main` ضمن تحديث وثائق UX.
