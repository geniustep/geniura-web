# 04 — التنقل والمصادقة وتحديد مساحة العمل

**الحالة:** تصميم مقترح، وليس تحويلًا موجودًا على الإنتاج.

## 1. خريطة المسارات

| المسار مع `/{locale}` | الوضع الحالي | الاستخدام |
|---|---|---|
| `/` | قائم | الصفحة العامة للجميع حتى مع وجود جلسة |
| `/jobs` | قائم | الوظائف بلا حساب |
| `/employers` | قائم | تعريف المؤسسات بالمنصة |
| `/login` و`/register` | قائمان | تسجيل الدخول وإنشاء حساب |
| `/account` | قائم | إعدادات الحساب واللغة وكلمة المرور |
| `/account/profile` | قائم | الملف المهني |
| `/account/profile/resumes` | قائم | السير الذاتية |
| `/account/profile/privacy` | قائم | إعدادات خصوصية الملف |
| `/account/profile/access-log` | قائم | سجل الاطلاع |
| `/workspace` | **مقترح** | بوابة اختيار السياق |
| `/workspace/candidate` | **مقترح** | لوحة الباحث |
| `/workspace/employer/[organizationId]` | **مقترح** | لوحة مؤسسة محددة |
| `/workspace/choose` | **مقترح** | اختيار السياق متعدد الأدوار |

**تعارض محفوظ:** `GENIURA-HOME-EXPERIENCE-MASTER-v1.md` يقترح `/dashboard` و`/employer/dashboard`؛ ملف المشروع `04-NAVIGATION-FLOWS.md` يقترح `/workspace/*`. اخترنا الثاني **لتوحيد هذا المرجع فقط**، لا لتنفيذه قبل مراجعة App Router والتفويض.

## 2. تسلسل التوجيه المقترح

```text
نجاح المصادقة
   |
   +-- يوجد next آمن ومسموح؟ --> الوجهة الأصلية (بعد اختبار الصلاحية)
   |
   +-- بدون next --> مساحة عمل موثقة من الخادم
                    |-- مرشح --> /workspace/candidate
                    |-- عضو مؤسسة --> /workspace/employer/{orgId}
                    |-- أكثر من سياق --> /workspace/choose
                    |-- لا عضوية مثبتة --> إدخال مهني أو onboarding آمن
```

**الواقع الآن:** `features/auth/login-form.tsx` يستعمل **`next`** وليس `returnTo`، ويحول عبر `safeRedirectPath(next)`، التي تعود افتراضياً إلى **`/account`**. لا تغير القيمة الاحتياطية قبل بناء صفحة محمية واختبارها، مع دعم وجهة الترشح المقصودة والعودة لها دون تقديم آلي.

## 3. الحماية

- `next` مسار نسبي داخل الموقع؛ رفض `//` والنطاقات الخارجية والبروتوكولات والـbackslash والترميز الخطير. أعد التحقق من الصلاحية للوجهة قبل العرض.
- `signup_intent=candidate|employer` **نية تسجيل**، لا تفويض للشركة.
- لا يُعتمد نوع الحساب من الواجهة؛ يستمد الدور والأعضاء المسموح لهم من Django.
- لا مزج حالة المؤسسة A مع B. عند تبديل المؤسسة ألغِ بيانات cache والسياق السابقين وجلب بيانات جديد.
- `/workspace/*` عند إنشائها لها حماية جلسة فعلية و`robots noindex` ورؤوس `private,no-store`، ولا تظهر في sitemap.
- لا تعيد التوجيه من صفحة عامة قسرًا لمجرد وجود جلسة.

## 4. قوائم الاستخدام

- **الزائر:** عروض العمل، للمؤسسات، كيف تعمل المنصة، اللغة، دخول/تسجيل.
- **الباحث:** نظرة عامة، ملفي، سيرتي، الوظائف، ترشيحاتي إن كانت الشاشة متاحة، حسابي.
- **المؤسسة:** نظرة عامة، عروضنا، الترشيحات، الفريق، الإعدادات، تبديل المؤسسة عند الحاجة.
- **الهاتف:** إجراءات واضحة وقائمة أو تبويبات لا تُخفي الإجراء الأساسي؛ تجنب شريط سفلي مزدحم أثناء التحرير.

## 5. اختبارات قبول خاصة

`next` آمن، تعدد الأدوار، عضوية موقوفة، انتهاء الجلسة أثناء التحرير، خروج وإبطال بيانات الجلسة القديمة، عدم تسرب بيانات المؤسسة عند تبديل المستخدم، وتوافق اللغات الأربع.
