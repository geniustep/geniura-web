**المرجع بتاريخ 29 أكتوبر 2026:** `geniura-web` على `dev`، `contracts/source.json` من `geniura-api@d626e1012e164d8ff71249d25ecdd875d12a6256`، **114 مسارًا و150 عملية**. هذا جرد عقد مولد ولا يثبت تشغيل الإنتاج.

## 1. مستويات إثبات مستقلة

`contract_exists` (العقد موجود) ≠ `screen_exists` (الشاشة منفذة) ≠ `runtime_verified` (اختبار تكامل ناجح) ≠ `production_ready` (مفعل ومقبول للإعلان). لا يُنشأ API جديد لمجرد غياب شاشة.

## 2. المصفوفة الواقعية

| عضويات المؤسسة | `Me.memberships` و`organizations` | اختيار مؤسسة غير منفذ | عناصر `MeMembershipsItem` مولدة كـ`Record<string,unknown>` |

## 3. قواعد الظهور

لكل وحدة: **loading** بمساحة ثابتة؛ **success** ببيانات حقيقية؛ **empty** بإجراء بديل؛ **partial** يبقي الوحدات العاملة؛ **error/503** برسالة وإعادة محاولة؛ **401/403** دون تسريب؛ **409/412** مع معالجة التعارض؛ **422** خطأ الحقل؛ **429** تهدئة؛ **feature_disabled** يخفي الرابط أو يوفر إدخالاً يدوياً. لا تُستبدل API الفاشلة بصفر أو بيانات demo.

## 4. أمان المصادقة والخصوصية

- `signup_intent` نية تسجيل وليس ترخيصًا لشركة؛ لا تعوّض غموض `MeMembershipsItem` بتخمين حقول.
- كل عملية مؤسسة مرتبطة بعضوية وسياق `org_id` مع تفويض backend وعزل A/B.
- مسارات `/workspace/*` المقترحة تُحمى عند التنفيذ عبر session و`noindex` و`Cache-Control: private,no-store` وعدم التضمين في sitemap أو shared cache.
- رؤوس الخصوصية الحالية في `next.config.ts` تغطي `/account` فقط؛ يحتاج التوسع للوحة الجديدة اختبارًا.
- مراجعة CV والموافقة صريحتان؛ لا ترسل CV أو الهوية أو معلومات الاتصال إلى أدوات التحليل.

## 5. واجبات وكيل التنفيذ

افحص `contracts/source.json` و`contracts/openapi.web.v1.yaml` و`lib/api/generated` والخادم الفعلي قبل أي endpoint جديد. لكل استعلام: operationId، نوع البيانات، pagination، الصلاحية، التفعيل، HTTP errors، سياسة cache، الاختبار، البديل. فصل مطلق بين تعديل `geniura-web` و`geniura-api` إلا بإذن.

تاريخ `contracts/README.md` يسرد مراحل أقدم؛ مصدر العقد الجاري عند الفحص هو `contracts/source.json`. لا يفيد هذا الجرد شيئًا عن أحدث نسخة محتملة من المستودع الخلفي الخاص.
