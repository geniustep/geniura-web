# 03 — الواجهة الرئيسية للمؤسسة بعد الدخول

**المعرّف:** UX-EMPLOYER-001. **المسار المقترح:** `/{locale}/workspace/employer/[organizationId]` (غير منفذ حالياً).  
**الهدف:** إظهار وضع المؤسسة والمهام المستعجلة والعروض والترشيحات المصرح بها، وليس نسخة من لوحة الباحث.

## 1. أول ما يظهر

- السياق: اسم المؤسسة من Backend، ومحدد المؤسسة **عندما تتعدد العضويات المصرح بها**.
- حالة التحقق من المؤسسة الفعلية، مع الفصل بين **تحقق المؤسسة** و**مراجعة الإعلان**.
- بطاقة «خطوتك التالية»: استكمال المؤسسة أو تحققها، ثم إنشاء عرض إن سُمح، ثم مراجعة ترشيحات تحتاج إجراء.
- بيانات تشغيلية مختصرة: عروض نشطة، ترشيحات جديدة، مهام انتظار **فقط من API مع تعريف واضح**. لا عدادات وهمية.
- قائمة أحدث عروض المؤسسة والترشيحات المرتبطة بها، وإجراءات حسب الدور.
- قسم خدمة التوظيف الاحترافي منفصل عن الإعلان، إن كانت الخدمة مفعلة.
- إدارة أعضاء الفريق والأدوار إن توافرت الصلاحية.

## 2. سيناريوهات المؤسسة

| الحالة | العرض الصحيح |
|---|---|
| حساب بلا عضوية | دعوة إلى إنشاء/الانضمام عندما تسمح الخدمة |
| عضوية معلقة أو مؤسسة قيد التحقق | صفحة حالة دون كشف موارد المؤسسة |
| نقص بيانات أو طلب استكمال | إجراء تصحيح مقيّد |
| مؤسسة نشطة بلا وظائف | «أنشئ أول عرض» فقط إن كانت صلاحية الإنشاء مثبتة |
| مؤسسة مع عروض | بطاقات/جدول بالمسمى، المدينة، الحالة، تاريخ النشر، الترشيحات |
| عضو قراءة فقط | محتوى مسموح دون أدوات تعديل؛ backend يرفض التجاوز |
| مؤسستان A وB | تبديل السياق يلغي cache المؤسسي السابق ولا يسرّب أي بيانات |
| API معطلة | خطأ واضح، لا عدادات صفرية كاذبة |

## 3. التوظيف والمرشحون

لا ترى المؤسسة ملفات مرشحين لم يتقدموا إليها أو لم يوافقوا صراحة على الاطلاع؛ لا تنزيل جماعي لقاعدة CV. تظهر مراحل الترشيحات من أحداث المصدر، لا من تخمين الواجهة. القرارات النهائية بشرية، والمطابقة الذكية — عند اعتمادها — تفسير مساعد لا رفض آلي.

الأدوار `owner/admin/recruiter/viewer` وغيرها تؤخذ من العقد الجاري؛ لا تُخترع `capabilities` على الواجهة، ولا يعتمد التفويض على `signup_intent` وحده.

## 4. تحقق الواقع التقني

في `dev` توجد صفحة `/employers` **عامة فقط**، بينما يتضمن العميل المولد عمليات مؤسسات وأعضاء `organizations`، وإعلانات `jobs-organization` وترشيحات `applications-organization`. **وجود هذه العمليات لا يثبت أن لوحة التشغيل مبنية أو جاهزة للإنتاج.**

نموذج `Me.memberships` موجود، لكن `MeMembershipsItem` مولد كـ`{[key:string]: unknown}`، ويجب تثبيت الصلاحيات وبنية العضوية من مصدر Backend قبل تنفيذ اختيار المؤسسة. لا يُعلن عن نشر مجاني للمؤسسات قبل قرار تجاري موثق.

## 5. شروط الحماية والاختبار

- تفويض عضوية المؤسسة من الخادم في كل طلب، واختبار 401/403 وعزل A/B.
- لا بيانات مرشحين في صفحات عامة أو تقارير تحليلات عامة.
- كل وحدة تتحمل `loading/empty/partial/error`، والفشل لا يتحول إلى رقم صفر.
- `/workspace/*` الخاص يجب أن يكون `noindex` و`private,no-store`.
- الهاتف يعرض بطاقات بدلاً من جدول عريض؛ زر رئيسي واحد للمهمة الحالية.
- لا تُفتح لوحة تشغيلية للمستخدمين حتى ينجح اختبار عقود الإعلانات والترشيحات والصلاحيات.
