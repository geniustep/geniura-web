# 05 — هوية Nuit والتصميم المتجاوب

## 1. هوية ثابتة معتمدة

- **Nuit:** كحلي عميق للمساحات البارزة، عاجي للأسطح المقروءة، ذهبي محدود على الخلفيات الداكنة، وأزرق للإجراء الرئيسي.
- استخدم الشعار الرسمي وحده، دون إعادة رسم أو تغيير حروف/نسب أو إدخاله في خلفية جديدة.
- المصدر الفعلي للتوكنات والمقاسات والخطوط: `styles/globals.css` و`styles/fonts.ts` وصفحة `app/[locale]/design-system`، والشعار من `components/layout/brand-mark.tsx`.
- الخطوط المعتمدة حسب المشروع: Readex Pro / Bricolage Grotesque للعناوين بحسب اللغة، وIBM Plex للنصوص حيث تستخدمه الشفرة.

**لا تُنشأ هوية بصرية ثالثة خارج Nuit.** يمكن إعداد 2–3 تخطيطات UX مختلفة داخل النظام نفسه للمقارنة، وليس ثلاثة شعارات أو ألوان متعارضة.

## 2. بنية عرض Desktop وMobile

| السياق | حاسوب | هاتف |
|---|---|---|
| العامة | 55–60% نص + 40–45% معاينة ملف مهني | عنوان، وصف، CTA، معاينة، ثم فوائد ووظائف |
| الباحث | مهمة أساسية بعرض كامل ثم ملف/ترشيحات وبقية الوحدات | مهمة تالية أولاً ثم بطاقات مفردة |
| المؤسسة | السياق والإجراء التالي ثم مؤشرات وفهرس عروض وترشيحات | بطاقات مختصرة بدلاً من جداول عريضة |

التصميم Mobile-first، واختبار 320 و375 و390 و768 و1280 و1440 CSS px؛ لا تمرير أفقي أو عناصر متداخلة.

## 3. السلوك البصري

- Hero واحد واضح، زر أساسي وزر ثانوي على الأكثر؛ رابط الوظائف نصي، ولا ينافس CTA.
- أهداف اللمس نحو 44×44 CSS px، ولوحة المفاتيح تعمل بالكامل.
- تصميم للحالات `loading/empty/error/success/partial` لكل وحدة.
- النص الحقيقي في الـHero يحمّل سريعاً، ولا ينتظر خدمة وظائف أو AI.
- لا صور stock مبتذلة، ولا نسب مصطنعة، ولا بطاقات تبدو قابلة للنقر وهي غير تفاعلية.
- عند استخدام معاينة بيانات منتج، اكتب «معاينة توضيحية»؛ لا تضع بيانات مستخدم فعلي.

## 4. اللغات والإتاحة

- `ar` افتراضية RTL، و`fr/en/es` اتجاهها LTR. أسماء الشركات والمهن متعددة اللغات تستخدم `bdi` أو `dir=auto` حيث يلزم.
- هدف WCAG 2.2 AA: تباين، Focus ظاهر، تسميات حقول، عناوين دلالية، رسائل الأخطاء قابلة للقراءة، عدم الاعتماد على اللون وحده.
- احترام `prefers-reduced-motion`، وتقليل CLS بارتفاعات متوقعة لرسوم الانتظار.
- فحص axe آلي **ومراجعة بشرية** في العربية والفرنسية والإنجليزية والإسبانية.

## 5. الأداء

صفحات عامة ببيانات SSR مفيدة، تحميل تدريجي لوحدات الحساب الخاصة، لا تسرب بيانات الجلسة إلى cache مشترك؛ الحفاظ على Core Web Vitals وSEO الخاص بالصفحات العامة دون التضحية بسلامة البيانات.
