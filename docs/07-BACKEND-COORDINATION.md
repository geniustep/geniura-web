# مطالب منسّقة مع وكيل Backend (geniura-api)

مصدرها التحقق من geniura-api@239ebd9 (كود + نسخة محلية غير معدّلة). لا يعدّل وكيل الواجهة المستودع الخلفي.

| # | المطلب | السبب | الأولوية |
|---|---|---|---|
| 1 | وصف غلاف التصفح الفعلي في OpenAPI لكل القوائم المصفّحة (13 مسارًا للواجهة + مسارات staff) | العقد يصفها كمصفوفة؛ الواجهة تصحّحها مؤقتًا في `contracts/overrides.json` | عالية |
| 2 | وصف `{count, results, locale}` لقوائم taxonomy الأربع | نفس السبب | عالية |
| 3 | مكوّن `ErrorResponse` واستجابات 4xx موثقة لكل عملية | لا مخطط خطأ في العقد رغم توحيده في الكود | عالية |
| 4 | رمز خطأ مميز لرفض CSRF (مثل `csrf_failed`) | حاليًا 403 `permission_denied` والتمييز يتم بنص الرسالة | متوسطة |
| 5 | قائمة `capabilities` لكل عضوية في `/auth/me` | حتى لا تشفّر الواجهة جدول الأدوار ← الصلاحيات | قبل PHASE 5 |
| 6 | `slug` و`updated_at` للوظيفة العامة، ونقطة خفيفة لـ sitemap | SEO وروابط مقروءة | قبل PHASE 3 |
| 7 | تسميات مترجمة مضمّنة للمدينة/المهنة/القطاع في `PublicJob` | تجنب طلبات taxonomy إضافية لكل نتيجة | قبل PHASE 3 |
| 8 | webhook موقّع لإعادة التحقق عند نشر/إغلاق/إخفاء وظيفة | إبطال الذاكرة المؤقتة العامة | قبل PHASE 3 |
| 9 | نسخة `openapi.web.yaml` مصفّاة يولّدها CI الخلفي مع checksum | بدل الاشتقاق اليدوي الحالي | متوسطة |
| 10 | إعدادات النشر: `SESSION_COOKIE_DOMAIN=.geniura.com`، CORS/CSRF trusted origins | شرط لعمل المصادقة عبر النطاقين (ADR 0002 للواجهة) | عند النشر |
| 11 | دمج dev في main وتجميد العقد v1 | العقد ما زال `1.0.0-dev` | عالية |
