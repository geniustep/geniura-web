# عقد حدود التكامل — Web ↔ API
الوثيقة التكميلية المرجعية: مستودع geniustep/geniura-api الخاص، docs/03-API-V1-CONTRACT.md. هذه واجهة توقعات وليست تنفيذًا.

## مبادئ
- API الإصدار v1 تحت /api/v1؛ لا اتصال مباشر بقاعدة البيانات من Next.js.
- المصادقة والأذون وحالات الموارد يقررها Backend؛ إخفاء أزرار الواجهة ليس أمنًا.
- اقترح Cookie HttpOnly Secure SameSite مع CSRF أو BFF آمن عند الحاجة؛ يثبّت وكيل Backend اختيارًا واحدًا موثقًا ومتوافقًا مع النطاقات والنشر؛ لا نخزن refresh tokens في localStorage.
- لا تكشف الواجهة أسرار الذكاء الاصطناعي أو وسائط التخزين ولا روابط طويلة المدة لوثائق المرشحين.
- تواريخ ISO 8601 UTC في API؛ العرض حسب إعداد المنطقة الزمنية، والأرقام المالية مع العملة MAD إذا استعملت.
- الطلبات القابلة للتكرار ذات آثار مالية أو إنشاء ترشح/أمر خدمة تحتاج Idempotency-Key عند اللزوم.
- الاستجابات المعيارية توثق أخطاء: code/message/details/request_id؛ وتصفح صفحات محدود وحد أقصى ثابت وترتيب مستقر.
- التصفية والترتيب على الخادم، مع ثبات الدلالة متعددة اللغات؛ تتطلب صلاحية قبل البحث في بيانات المرشحين.

## مجموعات نقاط النهاية المطلوبة مبدئيًا (تخضع للتجميد بعقد OpenAPI)
- session/auth: تسجيل، دخول، خروج، جلسة، استرجاع، تأكيد بريد، سلامة CSRF.
- candidate: ملف/مهارات/خبرات/لغات، visibility، موافقات، CV upload/finalize/parse-review/delete، ترشيحاتي.
- organizations: إنشاء وتحقق وحالة التحقق وعضويات ودعوات وصلاحيات.
- jobs: browse/search/detail، إنشاء/تعديل/نشر/إغلاق/أرشفة، طلبات الترشح.
- applications: ترشح/انسحاب، جدول مرشحين بحسب مؤسسة ووظيفة، انتقالات الحالة مع تدقيق.
- recruitment: إنشاء طلب انتقاء جماعي، حالات، موافقات، تكليفات، shortlist.
- assessments: تعريف معايير/اختبار/نتائج وشرح ومراجعة بشرية حسب المرحلة.
- training: فجوات مهارية وتوصيات موارد/مسارات وفق المرحلة.
- trust/admin: بلاغات، مراجعة مؤسسة وإعلان، سجلات تدقيق وتقارير.
- notifications: تفضيلات وأحداث وقراءة؛ القنوات الخارجية مشروطة بالقرار.
- dictionaries: مهن/مهارات/مرادفات/ترجمات، ومدن وقطاعات وإعدادات عامة.
- billing: أوامر خدمات تجارية وحالاتها فقط ما لم يعتمد تسعير ودفع.

## متطلبات استجابة الواجهة
- النتائج العامة لا تحتوي وسائل اتصال المرشحين.
- إظهار مصدر معلومة مهارة ومستوى التحقق وعدم تحويل extracted إلى verified تلقائيًا.
- فصل ملف المرشح المشترك عن notes/assessments الخاصة بالمؤسسات.
- خدمة البحث لا تُعيد مرشحًا خاصًا أو غير موافق على الاكتشاف.
- عقد حالات واضح مع رموز ثابتة ومعرّفات مستقرة، ونصوص مُترجمة في الواجهة.

## قبل بدء تطوير UI
ثبّت OpenAPI ومرّر أمثلة طلب/استجابة واختبارات تعاقدية؛ حدد جلسة المصادقة وCORS/CSRF، آلية رفع الملفات، حدود صفحات النتائج، وفلاتر البحث. لا تستنتج أن الـAPI موجودة حاليًا.
